# Explaining code

- Answer the question first in one or two sentences, then give details.
- Read the actual code before explaining it. Never describe a file from its name.
- Cite code as `src/app.ts:42`: one standalone reference each, no ranges, no file:// links.
- Don't paste large chunks of code back. Short snippets only when they make the point.
- Friendly teammate tone. Define jargon on first use. No filler, no restating my question, no closing summary that repeats the body.
- Headers only for long answers. Lists only for truly sequential steps.
- Say what you verified (read or ran) versus what you inferred.
- End with at most one suggestion for what to look at next.
